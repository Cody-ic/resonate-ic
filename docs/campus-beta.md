## 备份与恢复

每日北京时间 04:30 左右短暂停服务生成加密备份，完成或失败都会重新启动服务。SQLite 使用一致性快照，不直接拷贝 WAL 中间状态。当前备份不自动清理历史文件。

手动备份：

```bash
bash "$HOME/resonate-ic/current/scripts/campus-backup.sh"
```

恢复到全新的目录并核对哈希和 SQLite 表计数：

```bash
python3 "$HOME/resonate-ic/current/scripts/campus-backup.py" restore \
  --shared "$HOME/resonate-ic/shared" \
  --archive /绝对路径/备份.resbackup \
  --target /绝对路径/尚不存在的恢复目录
```

恢复默认隔离原始凭据、关闭外发，避免演练目录发送邮件或消耗 API。完整切换需明确配置恢复目录和服务，并核验密钥、最新预算、附件读取后再启动。

## 2026-10-29 邮件连接修复

校内服务器直接使用 workerd 请求 Graph 出现超时，Node 原生连接也出现连接超时；同机 curl IPv4/HTTP1.1 能正常连接。为微软 Graph 与 OAuth 两个主机增加独立出口适配，保留 TLS 证书校验，凭据和请求体仅通过 curl 子进程标准输入传递，不放在命令参数、文件或日志中。其余模型与仓库请求保留原来的传输路径，不自动重试结果不明的发信请求。

账号验证码申请返回限时签名的投递状态凭据；验证与找回页面分别显示排队、发送中、服务已接受、结果不明、失败与过期。查询不提供收件地址、验证码或邮件正文，凭据不能用于登录或验证账号。注册跳转后的投递状态仅在当前浏览器会话中保存。旧的不确定邮件保持原状态，过期验证码应重新申请。

部署时保留共享 D1、R2、DO 与 Workflow 的全局持久化配置，切换后检查 SmartWatch 和课程仍公开。23 项邮件单元与连接适配测试、35 项编译后账号邮件流程测试通过；真实验证码请求得到服务接受，维护者已确认 QQ 邮箱收到。密码没有被修改。

后续实测仍发现部分 Graph 请求在 TLS 握手约 0.2 秒后等待响应直至超时。出口改为从即时 DNS 结果中选择通过无收件人验证请求的连接地址，短暂缓存可用路径；探测不发送邮件，不改变 HTTPS 校验或所需权限。仅在 curl 明确证明实际请求尚未开始时允许队列稍后重试；已经发出而结果不明的邮件仍不自动重发。最后一次真实验证码请求约 2.2 秒获 Graph 接受，此时间不代表收件箱到达保证。

验证码改为 Better Auth 内置的加密存储与有效期内复用，10 分钟有效，保留最多 3 次错误尝试且重发不清零。页面增加重发倒计时、发送中禁重复申请、成功后禁重复确认，以及中文错误说明。切换前确认没有尚在有效期内的旧格式验证码，未使用用户截图中的验证码进行验证。25 项邮件单元测试及 39 项编译后邮件流程测试通过，浏览器使用无实际账号的测试输入确认中文错误提示。

后续真实服务器记录仍有发送请求等待 45 秒后超时的情况，可用地址探测未消除此故障。出口适配现在明确区分本地传输无响应与微软返回 HTTP 错误，避免 Miniflare 将本地异常转换成 500 后被误归因于微软；未知结果仍不会自动重发。诊断日志只增加传输阶段和字节计数，不包含凭据、验证码或邮件正文。此更改改善故障定位，不代表延迟或漏收已经解决。27 项邮件单元测试通过。

进一步同机、同一微软地址的无凭据对照：小请求约 0.27 秒返回 401；较大请求在默认 TCP 分段下两次均超时，将单条连接的 TCP_MAXSEG 设为 1200 或 1000 后分别约 0.29 秒返回。这指向校园服务器出口的大包传输问题，不能仅归因为收件方延迟。运行时改用 Python 标准库的单次 HTTPS 请求，仅该 socket 设置 TCP_MAXSEG=1200；保留默认 CA/主机名校验，OAuth 与发信凭据仍只走子进程 stdin。移除未解决问题的多地址探测与缓存，不修改主机全局路由或 MTU。curl 适配保留作诊断对照，不参与正式发信；已开始的 HTTP 写入仍不自动重试。

2026-10-30 部署 `campus-20261030-mail04` 后，隔离运行时经真实微软出口连续三次较大无凭据请求分别约 460/344/390 毫秒返回预期 401；29 项邮件单元测试、39 项隔离账号邮件流程测试通过。通过校园网站管理员入口发送的连接测试邮件已在 Outlook 收件箱核对；00:05:21 从校园网站申请的管理员 QQ 验证码，约 1.2 秒获微软接受，维护者随后确认实际收到。未向同学邮箱重发测试、使用同学验证码或修改其验证状态；SmartWatch 项目及课程仍保持公开。实际收件确认只覆盖本轮测试，不将 Graph 的接受状态记作通用送达回执。
