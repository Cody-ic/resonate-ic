# 购买云服务前的准备与发布验收

本文件不选择云厂商，也不代表已公网部署。现有后端仍依赖 Cloudflare 绑定；ECS 等普通服务器需要另行适配。

## 私有配置与管理员

复制 `config/production.env.example` 到 Git 忽略的私有环境文件，补齐真实域名、稳定管理员资料 ID 和凭据。执行 `node scripts/check-production.mjs <私有文件>`；该脚本只打印缺项，不打印值。服务器、数据库、对象存储、队列绑定仍须按最终方案配置，不能以脚本通过代替部署验收。

正式管理员需通过真实邮箱注册并验证，登录后从 `/api/me` 取得资料 ID，再设置 `ADMIN_USER_IDS`；验证普通账号无管理权限。`local_seedy` 仅本机测试，不能迁移为正式管理员。独立部署保持 `PLATFORM_AUTH_ENABLED=false`，禁止发布开发预览服务或通过伪造平台头登录。

新建空环境使用新随机 `BETTER_AUTH_SECRET`。**恢复已有数据库时不能直接换密钥**：邮件令牌和验证码正文依赖原密钥解密。完整恢复先保留配套密钥；如需轮换，应完成受控重加密或重新授权，并处理旧会话和在途验证码。Microsoft 刷新令牌会轮换，备份恢复后需核验，旧备份中的令牌不保证仍有效。不要同时运行恢复副本和原站的真实邮件、AI 队列。

## 备份与恢复演练

`scripts/local-backup.py` 是当前本机 Cloudflare 模拟运行数据的加密备份工具，依赖 Python `cryptography`。备份包含 `.wrangler/state`（D1/R2/DO/Workflow）和 `.dev.vars`，不包含源码和依赖，必须保留对应 Git 提交。它不是云端 D1/R2 导出工具。

1. 停止所有访问该目录数据的站点/队列进程。工具检查指定监听端口，同时要求明确 `--quiesced`；端口检查不能发现所有后台写入者。
2. `python scripts/local-backup.py backup --source <站点目录> --out <新归档.resbackup> --port 5173 --quiesced`。在终端隐藏输入独立备份口令，口令至少16字符，单独保管，勿写入源码或命令参数。
3. `python scripts/local-backup.py restore --archive <归档> --target <全新隔离目录>`。禁止覆盖既有目录。恢复验证认证标签、路径、逐文件 SHA-256 和 SQLite 完整性。
4. 恢复目录的 `.dev.vars` 默认关闭邮件、AI 调用和平台登录，清空管理员配置，暂停公开发布；原始配置放在 `recovery-secrets.original.env`，仅供核对和经确认的生产恢复。完整性核验在这些安全开关变更前执行。
5. `verify` 子命令验证恢复后的数据库表计数和 R2 blob 字节摘要。运行副本前仍需对应版本源码与依赖，并继续使用隔离、关闭外发的配置。

备份应保存到站点磁盘以外的受控位置。生产建议每日一次、升级前另存，保留最近7日及4周周备份；目前这是运维配置要求，不代表已设置定时任务。选定平台后补上云端导出和异地恢复流程。

## 日志与故障提醒

API 非预期错误只记录关联编号、接口类别、异常类型和时间，不打印请求正文、Cookie、令牌或原始供应商错误。用户收到关联编号可用于定位。现有审核/邮件失败会写管理提醒；**网站整机离线时站内提醒和同站邮件无效**，部署后需单独配置外部存活监测及站外提醒。日志权限、轮转和保留期限随生产平台确定。

## 生产验收顺序（以下在实际部署后执行）

- 配置 HTTPS、80跳转、域名及私有密钥，确认没有开发模拟身份入口；启动、重启后数据持久化。
- `node scripts/site-smoke.mjs https://实际域名`：匿名健康、目录配置、隐私/联系页面和权限隔离。此脚本只读、不调用邮件或 AI。
- 使用两个测试邮箱和一位正式管理员测试注册、邮箱验证、错误验证码、登录、退出、密码找回、过期会话、越权访问和校园共享出口；记录实际到信及垃圾邮件情况。
- 在专门的可清理测试内容上验收投稿→审核→通知、评论及回复语境、举报→核验→保留/下架→申诉。真实模型和邮件使用显式测试额度，不能以模拟响应冒充真实结果。
- 最终部署资源上重跑200账号读取、500账号校园NAT登录、50评论及逐条回复、5项目排队测试。逐条记录状态、等待时长、限流及失败原因；禁止自动重试掩盖首次失败。模拟模型并发与真实模型实测分开记录。
- 恢复备份到隔离环境；停机与恢复通知通道分别测试。确认以上完成后才开启公开发布。

当前隐私/联系页面对应 `/privacy`、`/contact`；公开前必须按实际托管方、运维主体及数据保存安排复核文字，不能把说明页当作已完成全部合规手续。
